# TrackPick Post-MVP 제품 백로그

> 상태: **Proposed**
>
> 최근 개정일: 2026-09-08
>
> 이 문서는 MVP 출시 이후 검토할 제품 아이디어를 관리한다. 아래 항목은 사용자 피드백을 바탕으로 수집한 후보이며, 구현 일정과 세부 정책은 아직 확정하지 않았다.

## 1. 사용자 피드백 기반 후보

| 항목 | 사용자 가치 | 현재 상태 |
| --- | --- | --- |
| 닉네임 랜덤 재설정 | 자동 생성된 익명성을 유지하면서 마음에 들지 않는 닉네임을 바꿀 수 있다. | 제안됨 |
| 내 추천 로그 | 자신이 소개한 곡과 그 곡이 받은 반응을 다시 확인할 수 있다. | MVP 반영 완료 |
| 개인 대시보드 | 추천 활동과 반응을 한 화면에서 파악할 수 있다. | MVP 반영 완료 |
| 한줄평 수정 | 추천 후 오탈자나 표현을 바로잡을 수 있다. | 미도입 확정, 작성 후 수정 불가 |
| 누적 데이터 활용 | 쌓인 추천·투표 데이터를 주간 차트와 발견 기능으로 확장할 수 있다. | 제안됨 |

## 2. 후보별 논의 사항

### 2.1 닉네임 랜덤 재설정

- 기존의 앞 단어, 뒤 명사, 숫자 네 자리 조합 규칙을 그대로 사용한다.
- 변경 횟수 제한, 재변경 대기 기간과 이전 닉네임 보존 여부를 결정해야 한다.
- 과거 추천 기록에는 변경된 현재 닉네임을 표시할지, 작성 당시 닉네임을 보존할지 결정해야 한다.

### 2.2 내 추천 로그

- `나의 활동`에서 추천 날짜, 곡, 아티스트, 한줄평, 최초 등록 여부와 해당 회차가 받은 Vote 수를 최신순 20개씩 제공한다.
- 과거 차트 당시 순위, 날짜·장르·반응순 필터는 필요성이 확인될 때 확장한다.
- 회원 탈퇴 시 추천·투표 기록을 삭제하는 현재 정책에 따라 탈퇴 후에는 내 추천 로그도 제거한다.

### 2.3 개인 대시보드

- 개인 기록 중심으로 추천 회차 수, 최초 등록 수, 받은 Vote 합계와 최고 Vote 곡을 제공한다.
- 경쟁 점수와 사용자 간 순위는 도입하지 않는다.

### 2.4 한줄평 수정

- 한줄평은 Recommendation 회차 생성 후 수정하지 못한다.
- 재추천 회차에서는 새 한줄평을 작성할 수 있으며 곡 상세는 최초 한줄평과 가장 최근 회차 한줄평 하나를 보여준다.

### 2.5 누적 데이터 활용

- 주간 가장 많은 Vote를 받은 곡과 주간 가장 많이 등록된 곡을 우선 후보로 둔다.
- `주간`의 시작 요일과 마감 시각, 재추천 회차 집계 방식, 동점 정렬 기준을 정의해야 한다.
- 유명 곡만 반복 노출되지 않도록 신규 발견, Hidden Gems 또는 상승 곡 같은 보조 목록을 함께 검토한다.
- 데이터가 충분히 쌓인 뒤 실제 분포를 분석하고 최소 표본 수와 노출 기준을 결정한다.

## 3. 우선순위 결정 기준

1. 사용자가 자신이 만든 추천과 받은 반응을 다시 확인할 수 있는가.
2. 기존 Daily Chart와 추천 정책의 일관성을 해치지 않는가.
3. 신고, 탈퇴와 과거 기록 보존 정책을 함께 처리할 수 있는가.
4. 운영 데이터가 기능을 의미 있게 만들 만큼 충분히 쌓였는가.

`내 추천 로그`와 `개인 대시보드`는 MVP에 반영했다. 나머지 제안 항목을 착수할 때는 제품 정책을 먼저 확정하고 baseline, user flow, ERD, OpenAPI와 테스트를 함께 갱신한다.
